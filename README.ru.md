Общайтесь со своими моделями Ollama прямо из Telegram. Ответ печатается по мере
генерации, диалог помнит контекст, а запросы не уходят дальше машины, на которой
запущена Ollama, — без облака и без оплаты за токены.

## Запуск в три команды

Нужны [Ollama](https://ollama.com) хотя бы с одной скачанной моделью и токен
бота от [@BotFather](https://t.me/BotFather).

```bash
cp .env.example .env          # укажите BOT_TOKEN и ADMIN_ID
uv sync
uv run python -m bot.main
```

Отправьте боту сообщение — ответ начнёт появляться раньше, чем модель закончит
генерацию. Команда `/models` переключает между всем, что показывает `ollama list`.

## Что происходит с сообщением

<p align="center">
  <img src="./assets/readme/flow.svg" width="100%"
       alt="Сообщение проходит проверку доступа и лимита, бот подгружает историю из SQLite, отправляет её в Ollama и дописывает ответ в то же сообщение">
</p>

Бот проверяет, что отправитель авторизован и не превысил лимит, подгружает
историю в пределах бюджета токенов, получает ответ из Ollama потоком и дописывает
его в уже отправленное сообщение. История и пользователи хранятся в SQLite,
модель работает там, куда указывает `OLLAMA_HOST`.

## Возможности

| Возможность | Что это значит на практике |
| --- | --- |
| **Потоковые ответы** | Сообщение обновляется по мере генерации, `/stop` прерывает ненужный ответ. |
| **Любая установленная модель** | Выбор для каждого пользователя из того, что отдаёт Ollama; `/model_info` покажет параметры, квантизацию и семейство. |
| **Изображения** | Отправьте фото vision-модели вроде `llava`. Бот сначала проверяет способность `vision` и честно сообщает, если её нет. |
| **Контекст по бюджету** | История обрезается по числу токенов, поэтому длинный диалог не переполняет окно модели незаметно. |
| **Свои инструкции** | `/system` задаёт системный промпт для каждого пользователя отдельно. |
| **Контроль доступа** | Писать боту могут только добавленные администратором; тестовый режим переживает перезапуск. |
| **Ограничение частоты** | Квота сообщений на пользователя, администратор её не расходует. |
| **Длинные ответы** | Ответ длиннее лимита Telegram в 4096 символов разбивается, а не обрезается. |

## Команды

**Для всех**

| Команда | Назначение |
| --- | --- |
| `/start`, `/help`, `/status` | Регистрация, справка, состояние бота и Ollama |
| `/models`, `/switch_model`, `/current_model` | Список, переключение и текущая модель |
| `/model_info [модель]` | Параметры, квантизация, семейство и шаблон |
| `/clear`, `/history`, `/regenerate` | Сбросить диалог, показать его, перегенерировать ответ |
| `/stop` | Прервать текущую генерацию |
| `/system [текст]` | Показать или задать системный промпт |

**Только администратор**

| Команда | Назначение |
| --- | --- |
| `/add_user`, `/remove_user`, `/list_users` | Управление доступом |
| `/stats` | Запросы и время ответа по моделям |
| `/test_mode` | Режим «только администратор» |
| `/clear_history` | Очистить сохранённые диалоги |
| `/broadcast` | Сообщение всем активным пользователям |

## Настройка

Обязательны только первые две переменные.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен от @BotFather |
| `ADMIN_ID` | — | Ваш Telegram user ID |
| `OLLAMA_HOST` | `http://localhost:11434` | Адрес Ollama |
| `OLLAMA_TIMEOUT` | `60` | Секунд ожидания данных; зависшая модель отбрасывается |
| `DEFAULT_MODEL` | `llama2` | Модель для тех, кто не выбрал свою |
| `MAX_CONTEXT_TOKENS` | `3000` | Бюджет токенов на историю диалога |
| `OLLAMA_KEEP_ALIVE` | `10m` | Сколько Ollama держит модель загруженной |
| `OLLAMA_TEMPERATURE` | значение модели | Температура сэмплирования |
| `OLLAMA_NUM_CTX` | значение модели | Переопределение окна контекста |
| `RATE_LIMIT_MESSAGES` / `RATE_LIMIT_WINDOW` | `10` / `60` | Сообщений за окно, в секундах |
| `MAX_CONCURRENT_UPDATES` | `32` | Событий параллельно, чтобы один долгий ответ не блокировал остальных |
| `DATABASE_URL` | `sqlite:///data/bot.db` | SQLite или PostgreSQL |
| `TEST_MODE` | `false` | Режим только для администратора |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `HEALTH_CHECK_ENABLED` / `HEALTH_CHECK_PORT` | `true` / `8080` | Эндпоинт `/health` |

## Docker

```bash
docker compose up -d
```

Compose монтирует `./data`, поэтому база переживает пересборку. Если Ollama
запущена на хосте, а не в сети compose, укажите адрес явно:

```env
OLLAMA_HOST=http://host.docker.internal:11434
```

Образы публикуются в GHCR при каждом пуше в `Master`:

```bash
docker run -d --env-file .env -v ./data:/app/data ghcr.io/fgeeha/tg-ollama:latest
```

## Разработка

```bash
uv sync              # установка вместе с dev-зависимостями
uv run pytest -q     # тесты
uv run ruff check src/
```

Миграции схемы применяются автоматически при старте, в том числе к базам,
созданным до появления миграций.

## Ограничения

- Для картинок нужна модель со способностью `vision`; бот откажется, а не
  отправит изображение текстовой модели.
- Ранее присланные изображения не отправляются повторно: модели сообщается, что
  картинка была, но сейчас недоступна.
- Одна генерация на пользователя одновременно; второе сообщение подождёт, а не
  смешается с первым.
- SQLite по умолчанию достаточно для личного бота. Для большего укажите
  PostgreSQL в `DATABASE_URL`.
